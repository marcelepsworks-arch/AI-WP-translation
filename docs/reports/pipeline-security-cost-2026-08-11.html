Steps 1–5 run automatically per content block (heading, paragraph, image caption, SEO field…). Step 6 is a local review report (logs/progress.html) generated after translation but before anything is sent to WordPress — every block's source and translation are shown side by side with its QA verdict. Only step 7, triggered explicitly by a person via app.cli.publish, ever writes to the live site — and always as a draft, never published automatically.

Why translation and review are two separate AI calls

A single combined request has already been shown to miss real technical errors during testing — see the worked example in the July executive summary (docs/reports/executive-summary-2026-07-23.html). Keeping the Reviewer independent of the Translator is a deliberate design choice, not an afterthought.

Security & quality controls

  • ✓Draft-only writes. Every translated page is created with WordPress status draft — this is not a runtime toggle, it is hard-coded, so a misconfiguration cannot accidentally publish a page live.
  • ✓Human review before publish. The new review-then-publish flow means translation and the WordPress write are two separate, explicit steps — nothing reaches the site without a person looking at it first.
  • ✓Per-block QA scoring. Every block is independently checked for numeric/unit mismatches, protected-term violations, and broken URLs, and flagged for human review rather than silently passed through.
  • ✓Protected terminology & content. Product names, model numbers and glossary-mandated terms are detected and never translated or altered by the AI.
  • ✓Faithful Elementor round-trip. Only known, translatable text fields are touched inside _elementor_data; every id, image reference, and layout setting is left byte-for-byte untouched — corruption or layout loss is not possible by construction.
  • ✓Correct WPML API usage. Translation linking uses the modern wpml_object_id filter rather than the legacy icl_object_id alias, after an empirically confirmed false-positive with the legacy call (see MEMORIA.md).
  • ✓Credential hygiene. WordPress access uses a dedicated Application Password (not the account login password), and all secrets are read from .env, never committed to source control.
  • ✓Automated regression coverage. 246 automated tests run against every change, with no live API calls in the test suite.

This system's range spans a short text-only page (∼$0.01–$0.02, matching the July measurements) up to a large page with many image fields and full QA (a real run on 11 August 2026 came to $0.2699 for a long page with 299 image references and 14 blocks flagged for human review). Even at the high end, that is roughly 500–1,500× cheaper than an agency quote for comparable technical content.

Why the gap is this large

  • No per-word billing. DeepSeek bills per token at $0.435 (input) / $0.87 (output) per million tokens for the translation model — a technical page's worth of text costs a fraction of a cent even with two independent AI passes.
  • Only changed content needs re-translating. The planned update-detection flow (WPML's native "needs update" status plus block-level content hashing) means a small content edit re-translates only the affected paragraph, not the whole page — agencies typically re-quote the full document.
  • The safeguards are what an agency editor would otherwise charge for. The independent Reviewer step, terminology enforcement, and numeric/unit checking are the same class of check a human proofreader performs — here they run automatically, at token cost, before a human ever needs to look at it.
In practical terms: a full first pass across the site's ~24 pages and 17 posts, even assuming every page were as large and image-heavy as the most expensive one measured so far, would total well under $10 in DeepSeek costs — against a five-figure agency quote for the same volume of technical content.
Caveat: the agency and generic-SaaS figures above are typical market ranges for technical translation, included for scale — not a quote obtained from a specific vendor. Actual agency pricing varies by language pair, volume discount, and contract terms.
