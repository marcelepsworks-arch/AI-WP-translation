Security & reliability — what to know before you click

Can the AI hallucinate? Yes, that's a real risk with any LLM-based translator — we don't hide it. That's why every translation goes through an independent Translator and Reviewer (two separate calls), plus three mechanical checks (numbers/units, protected terminology, URLs).

Does it publish itself, without human review? By default, never — every translation is written as a draft pending review. There is an optional autonomous mode (AUTO_PUBLISH_MODE in .env), off by default, that an operator must enable explicitly — whenever it's on, you'll always see a red banner at the top of this page, never silently. There's also a per-page "Publish directly" checkbox next to each Translate/Update button, for a one-off page without changing that global setting — it skips review for that page only, and ignores its own QA decision.

Could it cause a SQL injection or similar? Practically no, by architecture: this engine has no database connection at all — it only talks to WordPress through its authenticated REST API, the same path a human editor would use.

What if the AI generated dangerous HTML (<script>)? It's filtered through an allowlist before it reaches anywhere — app/qa/html_sanitizer.py.

This dashboard itself: it only listens on 127.0.0.1 (never reachable from outside your machine) and every action requires a secret token generated at each startup, so no other webpage open in another tab can trigger actions here without you knowing.

Full, honest detail (including real limits, not just what works well) in the project README.
